# FlashForge Finder 2 workbench

A local web page for model preview, experimental Orca slicing, GX thumbnails,
and explicit file saving/printing on a deliberately selected Finder 2.

## 1. Download the latest release

Requirements: **Linux x86_64**, Bash, Podman with a compatible Compose provider,
`curl`, `jq` and `unzip`. On Debian/Ubuntu, for example:
`sudo apt install podman podman-compose curl jq unzip`.
No host Node installation or test run is needed. First build needs Internet access
and several GiB of free disk space for the base image, packages and pinned Orca.

**Fresh installation only**; for an existing server, read [Upgrades](#upgrades).
Run these commands in **Bash** from the folder where you want to install:

```bash
mkdir finderlab-install
cd finderlab-install
url=$(curl -fsSL https://api.github.com/repos/mls-m5/flashforge-api/releases/latest | jq -r '.assets[] | select(.name | endswith(".zip")) | .browser_download_url')
curl -fL "$url" -o finderlab.zip
unzip finderlab.zip
```

This downloads the release's uploaded source ZIP, not GitHub's autogenerated
“Source code” ZIP; no GitHub login is required. For optional checksum verification,
use the [checksum-verified download](docs/ADVANCED_USAGE.md#optional-checksum-verified-download) instead.

## 2. Configure your printer and start

After a successful download and extraction, continue in the **same terminal**:

```bash
cd finderlab
cp .env.example.live .env
```

Edit `.env`: **set `FINDER_PRINTER_HOST` to your verified printer IP**.
For access from another computer, optionally set `FINDER_LISTEN_HOST` to this
**SERVER's specific 192.168 IPv4 address**, not the printer's. Otherwise keep
loopback. The live preset includes the proxy, profiles and workflow permissions.
Close FlashPrint/other control clients, then run:

```bash
./tools/start_server.sh
podman compose logs finder-web
```

The launcher runs `podman compose up --build -d`. For the default bind, open
**http://127.0.0.1:8000**. With a LAN bind, use `http://SERVER_IP:8000` even locally;
the server requires the exact configured IP in the URL, not `localhost`.
LAN login: user **finder**, initial password printed once in the private logs.
It persists as a salted hash across restarts; change it in the page's
**LAN login password** form. Do not publish logs containing the initial password.

## Essential safety

- Startup monitoring queries status only; it never starts/cancels a print.
- **Save + start is checked by default** and may heat/move. Uncheck for save-only.
  File receipt, Slice and page loading never start a print unattended.
- Trusted home LAN only: **HTTP is unencrypted**, including login and models.
  No Internet exposure, router forwarding or public tunnels.
- Experimental slicing/preview/guards are **not universal print-safety approval**.
  Inspect output and supervise hardware. Cancel is not an emergency stop.

## Upgrades

Wait until no operation is active. Preserve your private **`.env`, Compose
project name and persistent volumes**; never use `down -v` as upgrade cleanup.
Do not run old/new instances together. Follow [release/upgrade instructions](docs/RELEASES.md).
